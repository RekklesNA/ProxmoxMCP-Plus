# Independent review fixes

## Implemented

- Named-target job stores now use target-specific SQLite paths. `JobStore` also filters list queries and validates the persisted target metadata on every direct record lookup, so cross-target get/poll/cancel/retry operations resolve as unknown jobs.
- Named target command policies are instantiated and selected at invocation time for high-risk operations and retries; target toolsets receive the matching policy.
- Container command tools are registered when any configured target has SSH, including configurations with no legacy global SSH section. Invocation routes through the selected target toolset and its SSH configuration.
- Target `verify_ssl` is a strict boolean. Named-target API tunnel local host/port collisions are rejected during configuration validation.
- Job retry specs, metadata, results, audit events, last errors, and URL credentials/query secrets are sanitized before persistence and serialization. Base tool errors also redact URL credentials/query secrets.
- Added regression coverage for cross-target jobs, secret redaction, strict TLS values, and tunnel endpoint collisions.

## Remaining concerns

- The documented medium-level target-aware discovery/result annotation contract was not expanded beyond existing credential-free target discovery and target-specific routing.
- Persisted retry recipes are sanitized by design; a retry that requires a secret may not be restart-resumable from the persisted recipe alone, but no credential is written to disk or returned to callers.
